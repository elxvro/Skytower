# SkyTower v0.5 Reference UI & Progression Design

Date: 2026-10-01
Status: Design approved in chat; implementation not started
Target: Android / Google Play
Branch: `feat/skytower-v0.1`

## 1. Goal

Bring SkyTower v0.5 visually and functionally in line with the six approved reference screens without reinterpreting their style. The reference images are the visual authority for composition, hierarchy, color family, rounded-card language, purple title ribbons, coin presentation, lock states, green action buttons, and overall density.

The implementation must preserve the existing single-tap stacking game, offline-first architecture, local persistence, and current Android/CI toolchain.

## 2. Non-negotiable reference fidelity

The following screens must match the approved references as closely as practical within runtime Canvas rendering:

1. Theme Store
2. Daily Missions
3. Level System
4. Block Skins
5. Power-Ups
6. Enhanced Gameplay Screen

Rules:
- Do not introduce a new visual direction.
- Do not replace the purple ribbon headers with a different navigation style.
- Do not replace the white/light-blue rounded panel system with flat Material cards.
- Keep blue primary panels, green action buttons, dark navy price capsules, gold coin/crown accents, rounded lock badges, and the bright floating-island sky setting.
- Keep the SkyTower logo/header treatment consistent across all non-gameplay screens.
- Maintain portrait-first layout and scale proportionally across Android phone sizes.
- References control layout priority and visual hierarchy; implementation details may adapt only where required for legibility, touch targets, or aspect-ratio differences.

## 3. Architecture

Retain `SurfaceView` + custom Canvas for gameplay and menu rendering. Do not introduce Compose or a second rendering framework in v0.5.

Split the current large UI responsibility into focused components:

- `SkyTowerView`: owns frame loop, active screen, engine integration, and top-level touch dispatch.
- `SkyVisualKit`: reusable drawing helpers for headers, cards, coin capsules, lock badges, progress bars, green/blue buttons, tabs, and common typography.
- `ThemeShopScreen`: theme preview, selection, purchase state.
- `DailyMissionsScreen`: daily mission cards, claim state, streak strip, all-complete reward.
- `LevelScreen`: level/XP display, reward track, local statistics.
- `BlockSkinsScreen`: skin preview, ownership, selection, purchase state.
- `PowerUpsScreen`: power-up catalog, owned counts, selection/equip state.
- `GameplayHudRenderer`: enhanced score, coin, pause, combo, PERFECT feedback, vertical progress rail, and atmosphere transitions.

Each renderer receives immutable screen state and returns/owns explicit touch rectangles for interactive regions. Business rules remain outside drawing code.

## 4. Navigation

Add an internal screen enum/state machine:

- `HOME`
- `THEME_SHOP`
- `DAILY_MISSIONS`
- `LEVELS`
- `BLOCK_SKINS`
- `POWER_UPS`
- `GAMEPLAY`

The home/menu screen will expose entry buttons/cards for the new screens while preserving Play, sound, vibration, best score, coin balance, and selected theme.

All secondary screens include the same top-left back button used in the references. Back returns to `HOME`; no Android Activity proliferation is required.

## 5. Shared visual system

### Header
- SkyTower logo centered near the top.
- Rounded blue back button at top-left on secondary screens.
- Coin/crown capsule at top-right.
- Purple ribbon title directly below logo.

### Cards
- White/light-blue outer panel.
- Deep blue or sky preview cards.
- Large corner radius and subtle dark/blue outlines.
- Green buttons for actionable claim/select/purchase states.
- Blue buttons for neutral selection/navigation states.
- Greyed buttons for unavailable states.
- Dark navy coin price capsules.

### Typography
- Bold rounded display appearance using available Android fonts and Canvas stroke/shadow treatment.
- White titles on purple/blue surfaces.
- Dark navy body text on light surfaces.
- Gold/yellow highlight for levels, rewards, PERFECT, and premium accents.

## 6. Theme Store

Reference content hierarchy:
- Large current-theme hero preview.
- Current theme name and short description.
- 2x3 theme grid.
- Free/selectable states and locked price states.

v0.5 themes:
- Day
- Sunset
- Night
- Neon
- Space
- Aurora

Existing v0.4 ownership data must migrate without loss.

Theme store behavior:
- Owned theme: button shows selected or selectable state.
- Locked theme: button shows coin price and lock.
- Purchase succeeds only if local balance is sufficient.
- Successful purchase immediately unlocks and selects the theme.
- No network purchase or real-money currency.

## 7. Daily Missions

Daily missions replace the current one-time mission presentation with date-scoped missions while preserving earned coins and existing game history.

Daily set:
- Place 10 blocks — 20 coins.
- Get 3 PERFECT placements — 25 coins.
- Reach 50 score — 40 coins.

Behavior:
- Progress accumulates during the current local calendar day.
- Mission completion enables a green `Topla` claim button.
- Reward is paid only when claimed.
- Claim state persists for that date.
- New local date creates a fresh daily mission state.
- Completing and claiming all three enables a 100-coin all-complete reward, payable once for that date.

Daily streak:
- Track consecutive days on which the player claims at least one daily reward.
- Reference shows a five-day strip; v0.5 implements a 5-day local streak cycle.
- Missing a calendar day resets the active streak to day 1 on next claim.
- Day 5 grants an additional local bonus reward and begins a new cycle on the next eligible day.

No server clock is introduced; local device date is authoritative for v0.5.

## 8. Level / XP system

Add persistent XP and derived player level.

XP sources:
- +10 XP per successful block placement.
- +5 bonus XP per PERFECT placement.
- +score XP at run settlement, capped per run to prevent extreme runaway values.

Level calculation must be deterministic and pure Kotlin. Use an increasing requirement curve rather than a fixed amount per level.

Level screen reference behavior:
- Current level prominently displayed.
- XP progress bar with numeric progress.
- Reward track showing nearby levels and their rewards.
- Claimable completed-level rewards use green buttons.
- Future rewards show locked/coming states.
- Player statistics at bottom: total runs, best score, total PERFECT.

Initial v0.5 reward track examples:
- Level 2: 50 coins.
- Level 3: 75 coins.
- Level 4: unlock one cosmetic reward slot.
- Level 5: 100 coins.
- Level 6: one free basic power-up.

Rewards are claim-once and stored locally.

## 9. Block Skins

Add block appearance independent from background theme.

Skins:
- Classic — owned by default.
- Crystal — owned by default in v0.5 to match reference hero emphasis.
- Marble — 650 coins.
- Gold — 900 coins.
- Ice — 800 coins.
- Neon — 1200 coins.

Behavior:
- One selected skin at a time.
- Owned selection is free.
- Locked purchase uses coins.
- Skin changes block rendering only; collision geometry and gameplay logic are unchanged.

Rendering targets:
- Classic: current glossy blocks.
- Crystal: transparent/glass-like highlights, bright edge strokes.
- Marble: off-white stone base with subtle vein strokes.
- Gold: warm metallic gradient-like bands and specular highlights.
- Ice: pale cyan translucent treatment with crack/edge accents.
- Neon: dark block bodies with cyan/magenta luminous edge strokes.

## 10. Power-Ups

Power-ups are purchased with coins and stored as integer inventory counts.

Power-ups:

### Second Chance
- Price: 300 coins.
- On the first miss of a run, if equipped/available, consume one and restore the last valid tower state with a new moving block.
- Maximum one automatic rescue per run.

### Slow Time
- Price: 250 coins.
- Consumable activation before/during a run.
- Reduces moving block speed temporarily.
- Duration is time-limited and visible in HUD.

### Wide PERFECT
- Price: 350 coins.
- Temporarily increases PERFECT tolerance without changing actual overlap collision.
- Duration is time-limited and visible in HUD.

### Coin Multiplier
- Price: 400 coins.
- Applies x2 to run-earned coins only for one completed run.
- Does not multiply mission, streak, or level rewards.

Power-up screen:
- Four large reference-style cards.
- Price buttons on catalog cards.
- Bottom equipped/available inventory strip.
- Maximum three equipped slots shown visually as in the reference.

## 11. Enhanced gameplay presentation

The gameplay screen must move closer to the approved reference while preserving current physics.

Add:
- More prominent score/best-score card.
- Coin capsule at top-right.
- Pause button at top-right edge.
- Vertical progress/height rail on the left.
- Larger PERFECT burst typography and particles.
- Larger combo label with stronger glow/scale.
- More visible cut-fragment particles.
- Selected block skin rendering.
- Theme-driven atmosphere transition during tall runs.
- Smooth camera remains from v0.3/v0.4.

Atmosphere progression:
- Low tower: current selected theme baseline.
- Mid tower: stronger cloud/parallax tint and light shift.
- High tower: more dramatic horizon/sky accents.

This is presentation only; no gameplay advantage comes from atmosphere changes.

- unlocked block skin mask

## 13. Business-rule isolation

Create pure Kotlin rule/state units independent of Android Canvas:

- `DailyMissionRules`
- `LevelRules`
- `SkinRules`
- `PowerUpRules`
- `RunRewardRules` / extension of current economy rules

Rendering code must not calculate prices, XP thresholds, claim eligibility, or reward duplication rules.

## 14. Error / edge handling

- Insufficient coins: no balance mutation; keep locked state and provide short visual feedback.
- Repeated claim tap: reward granted once only.
- Date rollover while app is open: daily state refreshes on next menu/daily-screen entry or run settlement.
- Corrupt/negative stored numeric values: coerce to safe non-negative defaults.
- Invalid selected theme/skin after upgrade: fall back to default owned item.
- Power-up inventory cannot become negative.
- Second Chance cannot recursively trigger more than once per run.
- Coin multiplier cannot multiply non-run rewards.

## 17. Out of scope for v0.5

- Google Play Billing
- ads
- backend/cloud saves
- online leaderboards
- Google sign-in
- cross-device sync
- server-authoritative daily reset
- real-money purchases
- multiplayer

## 18. Acceptance criteria

v0.5 is acceptable when:

1. All six approved reference concepts exist as working in-app screens or gameplay presentation.
2. Their visual composition remains recognizably faithful to the references rather than being reinterpreted into another UI style.
3. Theme, mission, level, skin and power-up data persist across app restarts.
4. Purchases and claims cannot double-award currency/rewards.
5. Existing v0.4 progression data is preserved.
6. Core single-tap stacking behavior remains unchanged except when an explicitly equipped power-up applies.
7. All new pure Kotlin tests pass.
8. Android lint passes.
9. Debug APK and release APK/AAB build successfully in GitHub Actions.
