# SkyTower v0.5 Reference UI & Progression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the six approved SkyTower v0.5 reference screens and progression systems while preserving the existing single-tap stacking engine, offline persistence, and Android build pipeline.

**Architecture:** Keep the existing `SurfaceView` + Canvas runtime. Move business rules into pure Kotlin units, persist all new state through `GamePreferences`, split reference UI into focused screen renderers plus a shared visual kit, and integrate power-ups through explicit run state rather than rewriting placement physics.

**Tech Stack:** Kotlin 2.2.10, Android Canvas/SurfaceView, SharedPreferences, JUnit 4, Android API 36, AGP 8.13.2, Gradle 8.13, JDK 17.

**Spec:** `docs/superpowers/specs/2026-10-01-skytower-v0.5-reference-ui-design.md`

## Global Constraints

- `versionName = 0.5.0`, `versionCode = 5`, package `com.elxvro.skytower`.
- Keep compileSdk/targetSdk 36 unless a verified build requirement forces a change.
- Do not add Compose, backend, ads, billing, sign-in, cloud sync, or multiplayer.
- The six approved reference images are the visual authority; no alternate visual direction.
- Keep the existing single-tap stacking behavior unchanged unless an equipped power-up explicitly applies.
- Preserve v0.4 best score, coins, theme ownership/selection, tutorial state, sound, and vibration.
- All prices, XP thresholds, durations, reward eligibility, and duplication guards live outside Canvas drawing code.

## Review Focus

- Device date moves backward: never double-pay a daily/streak reward for a previously recorded date.
- Rapid/repeated taps on claim or purchase regions: currency/reward mutation occurs at most once.
- Existing v0.4 data contains invalid/negative/new-version-missing values: migration clamps safely without losing valid coins/theme ownership.
- App pauses during timed power-ups: active duration must not decrease while paused.
- Narrow/tall phone aspect ratios: reference hierarchy remains intact and touch regions stay usable without stretched cards.
