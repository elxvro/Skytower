# SkyTower v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first playable Android release of SkyTower with one-tap stacking, overlap cutting, perfect-placement combos, local settings, and CI artifacts for APK/AAB.

**Architecture:** Keep gameplay math in pure Kotlin classes so it can be tested independently from Android. The Android app is a single portrait `Activity` containing a custom `SurfaceView`; the view owns rendering/input while `GameEngine` owns deterministic simulation state. Persistence, sound and haptics are small Android adapters around the pure engine.

**Tech Stack:** Kotlin 2.2.10, Android Gradle Plugin 8.13.2, Gradle 8.13, JDK 17, minSdk 26, compileSdk/targetSdk 36, JUnit 4.13.2.

**Spec:** `docs/superpowers/specs/2026-10-01-skytower-design.md`

## Global Constraints

- Android only, portrait only, package `com.elxvro.skytower`.
- Minimum API 26; compile/target API 36.
- Native Kotlin + custom `SurfaceView`; no game engine and no network dependency.
- No accounts, ads, billing, analytics, backend or cloud save in v0.1.
- Gameplay, best score, settings, audio and visuals work offline.
- CI runs unit tests, lint, debug APK, release APK and release AAB tasks.

## Review Focus

- Complete miss must never increment score and must enter game-over exactly once.
- Near-perfect placements at the tolerance boundary must snap without shrinking width.
- Very large frame delta after backgrounding must be clamped so the moving block cannot teleport through bounds.
- Repeated taps during a state transition or pause must not place multiple blocks.
- Restart must clear transient run state but leave persisted best-score/settings untouched.
